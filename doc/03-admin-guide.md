# Раздел 3. Руководство системного администратора

## 3.1. Системные требования

| Параметр | Значение |
|----------|----------|
| ОС | Android 7.0 (API 24) и выше |
| ОЗУ | от 2 ГБ |
| Свободное место | от 50 МБ |
| Интернет | не требуется (приложение работает полностью офлайн) |
| Разрешения | приложение не запрашивает никаких разрешений |
## 3.2. Установка

### Через Android Studio

1. Откройте проект (`File → Open`, корневая папка репозитория).
2. Дождитесь синхронизации Gradle.
3. Подключите устройство с включённой отладкой по USB или запустите эмулятор.
4. Запустите конфигурацию `app` (Run).

### Через APK

1. Соберите отладочный APK: `gradlew.bat assembleDebug` (Windows) или `./gradlew assembleDebug`.
2. Файл: `app/build/outputs/apk/debug/app-debug.apk`.
3. Передайте APK на устройство и установите его (при необходимости разрешите установку
   из неизвестных источников).

Идентификатор пакета: `com.example.socialnetwork`.

## 3.3. Расположение данных

База данных хранится по стандартному системному пути:

```
/data/data/com.example.socialnetwork/databases/social_network.db
```

Рядом создаются служебные файлы SQLite: `social_network.db-wal`, `social_network.db-shm`.

Фотографии публикаций копируются в приватную папку приложения:

```
/data/data/com.example.socialnetwork/files/post_images/post_<время>.jpg
```

Файл удаляется автоматически при удалении публикации.

Сессия пользователя и выбранная тема хранятся в `SharedPreferences`:

```
/data/data/com.example.socialnetwork/shared_prefs/circle_session.xml
/data/data/com.example.socialnetwork/shared_prefs/circle_settings.xml
```

## 3.4. Демонстрационные данные

При первом создании базы (`SQLiteOpenHelper.onCreate`) автоматически добавляются:

- 4 пользователя: `anna`, `max`, `lena` (пароль `123456`) и `admin` (пароль `admin123`);
- 6 публикаций в разных категориях;
- комментарии, лайки и подписки между ними;
- 4 личных сообщения (у `anna` есть непрочитанные от `max` и `lena`).

Пароли хранятся в виде SHA-256 от строки `соль:логин:пароль`, в открытом виде в БД их нет.

## 3.5. Обслуживание

- **Полный сброс данных**: «Настройки → Приложения → Круг → Хранилище → Очистить данные».
  При следующем запуске база создастся заново вместе с демо-данными.
- **Сброс сессии без удаления данных**: «Выйти из аккаунта» в профиле.
- **Обновление версии схемы**: при увеличении `DbContract.DB_VERSION` метод `onUpgrade`
  выполняет миграцию. Версия 2 добавляет таблицу `messages` и колонку `posts.image_path`,
  сохраняя существующие данные и дополняя базу демонстрационными переписками.
- **Резервное копирование** (на устройстве с root или через `adb`):
  ```bash
  adb exec-out run-as com.example.socialnetwork cat databases/social_network.db > backup.db
  ```

## 3.6. Панель администратора

Доступна пользователю с ролью `admin` (демо-вход `admin / admin123`):

- статистика: число пользователей, публикаций, комментариев, лайков и заблокированных;
- список всех пользователей с ролью и статусом;
- **Заблокировать / Разблокировать** — заблокированный пользователь не может войти,
  его публикации скрываются из ленты;
- **Удалить** — удаляет пользователя и каскадно все его публикации, комментарии, лайки,
  подписки и личные сообщения.

Собственный аккаунт администратора заблокировать и удалить нельзя.

## 3.7. Журналы

Ошибки фоновых операций с базой данных пишутся в Logcat с тегом `AppExecutors`.
Для просмотра:

```bash
adb logcat -s AppExecutors
```
